## 3. INSPECTOR DESIGN (what you plug in)

All slots live on the **GameView** component (the one component you attach),
so nothing new needs wiring:

```
GameView
  Node Prefabs
    Use prefabs:          [x]   (uncheck = old colored primitives, for fallback)
    Raw hubs:
      [ ] Wood             (drag Node_Wood here)
      [ ] Metal
      [ ] Energy
      [ ] Water
    Factories:
      [ ] Chips
      [ ] Mech Parts
      [ ] Building Mats
      [ ] Food
  Camera
    Pan speed:            20
    Zoom min:             10
    Zoom max:             60
    Edge scroll:          [x]
    WASD pan:             [x]
    Right-mouse drag:     [x]
    Mouse wheel zoom:     [x]
```

Rules:
- Slot empty (null) -> falls back to today's primitive marker for that type.
- `Use prefabs` off -> exactly the current look (safety net).
- You can mix: plug in 3 factories and leave the rest empty; only the
  plugged types change.

## 4. MAP GENERATION FLOW (code side, no GameSimulator changes)

`GameView.BuildMap()` per node, after `S.NewGame()`:
1. Ownership plane (the flat colored "territory" disc) — kept as-is,
   colored by `GameSimulator.ColorOf(node)`. (See Q2 if you want it gone.)
2. **Prefab**: instantiate
   `IsFactory ? factoryPrefabs[(int)Produced[0] - 4] : rawNodePrefabs[(int)Produced[0]]`
   at the node's grid position, parented under `NodeMap`, collider removed.
3. Label: floating name above the node (TextMesh, as today) — see Q8.
4. Ownership changes (you buy a node / buyout) -> existing `Refresh()`
   updates colors; if you choose "owner tint" (Q2) we tint the prefab's
   shared material too.
5. RESTART (`NewGame`) -> map is fully rebuilt, so new random node types
   automatically pick up their prefabs.

Authoring notes for your prefabs (so they slot in cleanly):
- **Pivot at the base** (bottom-center of the model) — the code places it
  at grid position with no extra offset.
- Roughly similar footprint (they sit on a 5-unit grid spacing); a model
  ~2-3 units wide reads well at the default camera.
- No colliders / scripts on the prefab; flat shading or lit both fine.
- If a prefab is a hierarchy, that's fine — we instantiate the root.

## 5. CAMERA CONTROL SYSTEM

New file: **`CameraController.cs`** (standalone MonoBehaviour, auto-used by
GameView when present; GameView's hardcoded `SetupCamera()` is retired).

### Inputs (defaults, all toggleable in Inspector)
| Action | Input | Notes |
|---|---|---|
| Pan | **WASD / arrow keys** | speed = `PanSpeed` units/s |
| Pan | **Right-mouse drag** (or middle) | 1:1 drag feel |
| Pan | **Screen edge scroll** | optional toggle |
| Zoom | **Mouse wheel** | clamped to ZoomMin/ZoomMax, zooms toward cursor |
| (Q4) | **Left click on node** | select node — see section 6 |

### Behavior
- Works with perspective or orthographic camera (see Q5).
- Camera pitch fixed (set once on Start: current ~angled top-down look, or
  straight down if you prefer — Q5).
- **Bounds clamp**: pan/zoom is clamped so the camera can't leave the map
  (map extent computed from node positions + margin).
- **UI-safe**: panning/zooming is disabled while the mouse is over an IMGUI
  panel, so dragging in a list never moves the camera.
- Inspector-tunable: pan speed, zoom min/max, edge scroll speed — no code
  edits needed to feel it in.

## 6. NODE INTERACTION (optional, pending Q4)
- Left-click raycasts from camera to map plane -> hits a node -> that node is
  "selected": outline/scale pulse on it, and the Nodes panel row is
  highlighted.
- Hover: subtle highlight so you know you can click.
- This makes prefabs *interactive*, not just decorative.
