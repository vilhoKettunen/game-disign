================================================================
 PROJECT PLAN — "Recource" (Unity Game Design Course)
================================================================

1. OVERVIEW
----------------------------------------------------------------
A Unity project for the game design course. The goal: design a small,
playable company game while keeping the design documentation (the GDD
hub) and the code in sync: every mechanic is first written down as a
design note, then implemented in code, with [[links]] connecting the two.

This file is the master plan: it tracks the project map, the working
conventions, the roadmap, and the next actions. Update it as things
progress — check off finished tasks and add new ones.

3. DESIGN DECISIONS (locked in)
----------------------------------------------------------------
  Core fantasy : Run a company. Take over resource hubs, trade their
                 output to grow. Pay taxes to the central government
                 (fixed 30% on all production + voluntary extra taxes)
                 to earn political points. Use points to take over
                 unclaimed government nodes. Win = become the most
                 powerful company in the country.
  Complexity   : EXTREMELY SIMPLE. No deep systems — keep each system
                 to its smallest useful form (see the plan docs).
  Playthrough  : ~10–60 minutes.
  Team         : 4 people total; 2 working on it for now.
  World        : (draft) a simple node map — hubs + government nodes.
  Time model   : (draft) simple ticks (a button or slow timer
                 advances production, taxes and the market at once).

4. CONVENTIONS
----------------------------------------------------------------
  * Design-first: a mechanic is written in the GDD hub BEFORE coding.
  * One C# class per file, inside Assets/scripts/.
  * The GDD hub links to code with [[ClassName]] style links
    (e.g. [[materials]]), so docs and code stay connected.
  * Each plan doc is a QUESTION FRAME: answer the questions, check
    them off, and it becomes the design doc for that system.
  * This plan is the single source of truth for "what is next".
    When a task is done, mark it [x]. When a new task appears,
    add it to the right phase or to the NEXT ACTIONS list.

6. CODE MAP (what exists now)
----------------------------------------------------------------
  materials.cs    ResourceType/ModuleType enums + MaterialCatalog
                  (resources, recipes, prices, module costs)
  Company.cs      company state: inventory, political power, tax state
  Node.cs         node/hub/factory: produced, inputs, modules, capacity
  Market.cs       government prices, re-rolled each tax cycle
  GameConfig.cs   all tunables (tick speed, tax, nodes, AI) - Inspector
  GameSimulator.cs core logic: NewGame, DoTick, Produce, TaxTick,
                  purchases, modules, trading, AI, win/lose
  GameView.cs     flat colored node map + IMGUI panels + controls
