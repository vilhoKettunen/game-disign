## 2. CURRENT STATE (what changes)
- `GameSimulator.NewGame()` (GameSimulator.cs ~line 110-160) is the ONLY place
  nodes are created: it loops `config.TotalNodes`, randomly picks raw/factory
  types, and places them on a fixed 5-column grid:
  `n.Position = new Vector2((i % 5) * 5f, (i / 5) * 5f);`
- `GameConfig` holds `TotalNodes`, `CompanyCount`, ... but nothing about shape.
- `GameView.BuildMap()` reads `S.Nodes[].Position` - it does not care HOW the
  nodes were created. So the map system can live entirely around NewGame()
  without touching rendering.

**The clean cut:** MapGenerator produces `List<MapNodeSpec>` (position +
optional type) and `NewGame(specs, settings)` uses them instead of its own
loop. Everything else (companies, ownership, production) stays as-is.

## 3. MAP SHAPE FORMAT - WHERE DO MAPS COME FROM?

Option A — **ScriptableObject grid (recommended default)**
A `MapDefinition` asset: rows of characters, e.g.
```
"........"
"..WWW..."
".M....E."
"....FF.."
"X......."
```
Legend: `.` empty, `W/M/E/W2` = raw type, `F` = factory (type randomized),
`?` = random raw, `X` = blocked/decoration, `N` = any node.
- Pros: premade maps are just assets, easy to diff/version, easy to
  serialize custom maps, setup screen lists them automatically.
- Cons: you type the shape instead of building it in a scene.

Option B — **Scene-based slots**
You place "MapSlot" prefabs in a scene to draw the shape; the generator reads
their positions at runtime.
- Pros: matches your "I will make a custom map scene" statement; WYSIWYG.
- Cons: a map = a scene; saving/loading custom maps is harder; harder to
  offer "choose from premade maps" in one build.

Option C — **Both (scene = live custom maps, SO = premade library)**
Editor-only helper that exports the scene layout into a `MapDefinition` asset.
Most flexible, most work.

[default: A now, structure it so C can be added later]
